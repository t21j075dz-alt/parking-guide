# 駐車場空き区画案内

添付された HTML・CSS・JavaScript をもとに、既存の4画面を維持して機能を追加した版です。ビルドや外部ライブラリは不要です。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | 4画面、施設の絞り込み、位置情報の状態表示、運転確認ダイアログ |
| `styles.css` | 共通の色・文字・余白、スマートフォン表示、ダイアログ |
| `app.js` | 施設データ、絞り込み、距離、デモ区画検索、画面遷移 |
| `location-safety.js` | 位置情報の継続取得、移動の推定、操作時の運転確認 |

4ファイルを同じフォルダーに配置し、`index.html` を開いてください。スマートフォンで位置情報を使用する場合は、HTTPSで配信したURLを開き、端末とブラウザーの位置情報利用を許可してください。PC上の開発確認には `localhost` も使用できます。スマートフォンからPCのHTTPのIPアドレスへ接続した場合は、この条件を満たしません。

## 追加した機能

### 利用中の位置情報

- 「現在地の取得を開始」を押した後、`watchPosition()` で現在地を継続取得します。
- 施設選択・条件選択・検索結果・案内の各画面で取得を続けます。
- 「現在地の取得を停止」で停止できます。再開は開始ボタンから行います。
- 別タブ・別アプリ・画面ロックなどで非表示になると一時停止し、表示に戻ると再開します。手動停止後は自動再開しません。
- 取得時刻・測位精度・移動状態を表示します。許可拒否時は停止し、一時的な取得エラーは再試行します。
- 位置情報はメモリー内で処理し、保存・送信しません。保存するのは従来の文字サイズ設定だけです。
- 位置情報がない場合や古くなった場合は、施設カードをデモ距離に戻します。
- GPS更新時は距離表示だけを更新します。「近い順に並べ替え」、条件変更、施設画面への復帰時に並べ替えます。自動更新で操作中のカードの位置が変わることを避けるためです。

ブラウザー版は、ページを閉じた後やバックグラウンドでの常時取得を提供しません。更新間隔と測位方法は端末・ブラウザーに依存し、高精度を要求しても常にGPSで測位されるとは限りません。

### 移動中に操作した場合の確認

- 精度と時刻を確認した複数の測位結果から移動を推定します。端末が速度を返さない場合は、位置の変化と経過時間から推定します。
- 移動を検知した状態でタップ・キーボード操作・スクロール等をすると、操作を止めて「運転中ですか？」と確認します。
- 「いいえ、運転していません」を選ぶと操作できます。この回答は最大5分間有効で、停止判定や位置取得の中断・再開でも失効します。
- 「はい、運転中です」を選ぶと画面操作を停止します。GPSが移動を示している間は再開できません。
- 再開には「安全な場所に停車したので再開する」の明示操作が必要です。GPSで停止を確認できないときは、その旨を表示し、利用者本人による安全な場所への停車確認を求めます。
- 確認前に止めた操作は自動実行しません。操作可能になったら、目的のボタンをもう一度押してください。
- GPSの取得が途切れても、すでに検知した移動に対する確認の必要性を自動解除しません。
- 既存のWebMCP連携による検索にも同じ確認を適用します。

GPSだけでは運転者と同乗者を区別できません。徒歩や公共交通での移動でも確認する場合があり、測位の精度が低い場合・位置取得を停止した場合は移動を検知できません。実際の運転状態を保証する機能ではありません。

### 施設の絞り込み

- 都道府県・市町村・カテゴリの3条件をAND条件で組み合わせます。
- 都道府県を選ぶと、その都道府県に登録されている市町村を選べます。都道府県変更時は市町村をリセットします。
- 都道府県と市町村の選択肢は `FACILITIES` から作るため、施設の追加に追従します。
- 「絞り込みを解除」で全施設を再表示します。該当件数と0件時の案内も表示します。
- 現在の10施設は岡山県8件・福岡県2件です。カテゴリはホームセンター3件・スーパーマーケット6件・実験用駐車場1件です。
- ドラッグストアの選択肢はありますが、元データに該当施設がないため0件になります。架空の施設は追加していません。

施設を追加する場合は `app.js` の `FACILITIES` に `prefecture`、`municipality`、`category` を含むレコードを追加します。市町村は「岡山市」「北九州市」のように市単位で登録しています。新しいカテゴリは `CATEGORY_LABELS` に表示名を追加します。

## コードとコメントの統一

- UTF-8・LF・2スペースのインデントを使用します。
- JavaScriptは `const` / `let`、ダブルクォート、セミコロンを使用し、条件分岐には波括弧を付けます。
- まとまりごとに共通形式の区切りコメントを置き、関数の説明は日本語の `/** ... */`、処理理由の補足は `/* ... */` にそろえます。
- 表示用語は「駐車区画」「空き区画」を基本とし、過去の追加経緯だけを示すコメントは整理しました。
- デモデータとGPSの実測情報を区別し、施設データは `textContent` で表示します。
- 元CSSの末尾の閉じ括弧不足を修正し、検索中にホームへ戻った場合に古い結果が残る処理も修正しました。

## 移動判定の調整

`location-safety.js` 冒頭の `CONFIG` で変更できます。現在の主な値は次のとおりです。

| 項目 | 値 |
| --- | --- |
| 移動の目安 | 5 km/h以上を4秒以上、複数回確認 |
| 停止相当の目安 | 2 km/h以下を15秒以上、複数回確認 |
| 移動判定に使う測位精度 | 35 m以内 |
| 位置情報の有効期間 | 20秒 |
| 測位間隔の上限 | 15秒 |
| 運転していない回答の有効期間 | 最大5分 |
| 一時エラーの再試行待ち時間 | 10秒 |

これらは試作の初期値です。実機の受信状況や移動速度に応じた評価・調整が必要です。施設の座標・空き台数・区画・案内経路は元のデモデータであり、実際の駐車場を案内するための情報ではありません。

仕様の参照先：[W3C Geolocation](https://www.w3.org/TR/geolocation/)。位置情報の許可、HTTPS、表示中の取得、速度の単位などを確認しています。

## 確認結果

模擬GPSと仮想時刻を使ったChromeの自動テスト35項目が成功しています。GPS監視の重複防止、監視IDが0の場合の停止、古いコールバックの無効化、取得エラーと復帰、非表示からの再開、速度未提供・精度不足・200ms間隔の更新、運転確認前の操作遮断、回答の有効期限、運転中の操作停止、入力値の復元、3条件の絞り込み、検索中のリセット、既存の画面遷移を確認しました。

320px・390pxの幅で、通常文字と大きい文字の4条件を画像とレイアウト測定で確認しました。画面とダイアログに横はみ出しはなく、運転中回答後のフォーカス移動も確認しています。360px幅も自動テストで確認しています。

実際のスマートフォンのGPS・Safari・画面ロック復帰は未検証です。実機では安全に停車した状態、または同乗者による操作で、位置情報の許可、画面切り替え後の再取得、誤検知の有無を確認してください。
